# 仕様の要点

正本は[仕様書](https://claude.ai/artifact/5LsjGgoao8uW32vUDHdvr4)。ここは実装中に手元で見るための要約で、食い違ったら仕様書を優先する。

## ルール
- 地域をタップするたびに 4 色を循環（白には戻さない）。全域が着色済みで同色の隣接が 0 になったらクリア
- 同色の隣接境界は赤でハイライト（ON/OFF 切り替え、初期 ON）。OFF のときは全域を塗り終えても衝突が残る場合だけ「同じ色の隣りあいが n か所」と知らせる
- タイマーは最初のタップで開始、クリアで停止、0.1 秒単位
- 飛び地は同じ地域として扱い、色も一緒に変わる
- ピンチで拡大縮小、ドラッグで移動。動かさずに離したときだけタップ
- 記録は保存しない（localStorage も使わない）。アカウントもサーバー処理も持たない

## ステージ
入門（地方・4〜10 地域）／本編（県を地域に分けた市区町村・15〜25、上級「まるごと」30〜180）／全国（47 都道府県）。解放制はなく最初から全部選べる。ステージ間の隣接は扱わない。

## 決定事項（仕様書の未決項目について、2026-11-15）
- **本編の区分**: 数で切らず、県などが実際に使っている地域区分を採る。対応表は `scripts/areas.py`（出典 URL つき）
- **粒度**: 愛知・神奈川の試作（県の地域区分の 1 階層、1 ステージ 5〜18 地域）で人間が了承。仕様書の目安 15〜25 より小さいステージも許容
- **政令市**: 政令市だけで 1 地域になる場合は区ごとに分ける（そうしないとステージにならない）。他の市町村と同じ地域に入る場合は市で 1 つ
- **分けない県**: 市区町村が 25 以下の県は 1 ステージ（仕様書の目安の上限。人間の確認はまだ）
- **ステージの格付けはしない**: 「入門」「本編」の区別をやめ、全部同じ扱いにする（人間の指示「全部本編です」）。選択画面は 地方ごとの都道府県 → その県のステージ、の順に並べ、日本地図（47 地域）は最初に大きなステージが来ないよう地方のあとに置く（人間の指示）。地方（学校で習う 8 地方区分）の都道府県ステージは、地方の見出しに並べる
- **デザインの方針**（モック案 1〜4 への人間の感想、2026-11-15。比較ページだった `mocks/index.html` は削除済み。コミット ad4e570 の履歴にある）
  - 選択画面で、塗り分け済みの地図の絵を見せない（ネタバレになる）。塗っていない輪郭なら可。クリア画面は自分の結果なので可
  - 4 色それぞれに模様を重ね、色だけに頼らない（賛成）
  - 同じ色の隣り合いを白黒の破線で示すのは、むしろ分かりづらい
  - 案 5・6（孔版印刷、強い色）は「ギラギラしすぎて嫌い」。案 1・4 の落ち着いた感じが好み。この方向で詰める（改訂版は design-1b・design-4b。同じく履歴にある）
  - **採用**: 案 1b を基本にする（書体 BIZ UDP ゴシック／明朝は「万人受けする」）。県のページだけは案 4b の考え方で、各ステージの小さな地図を「県全体の輪郭の中で、そのエリアを濃く示す」形にする
- **共有**（2026-11-15。モックだった `mocks/share.html` はコミット ad4e570 の履歴にある）
  - 共有画像は 4:5（1080×1350）。中身は仕様どおり地図・ステージ名・タイムの 3 つだけ
  - 文面は「短く」: `愛知県 名古屋市を 1:12.4 で塗り分けた！ #四色ぬりわけ` ＋ゲームの URL
  - 画像の保存・画像のコピー・文面のコピーを用意する（人間の指示）。端末の共有機能が使えない環境では押せない表示にして、ほかの方法を案内する
  - SNS のボタンが渡せるのは文面と URL だけ（画像は渡せない）。並べるのは X・LINE・Bluesky・Misskey・Mastodon（人間の決定）。Misskey は misskey-hub.net/share、Mastodon は share.joinmastodon.org（どちらも公式の中継ページで、利用者が自分のサーバーを選ぶ）
  - 実機の確認（2026-11-15、開発用の環境 https://four-coloring-game-dev.smooth-pudding-1017.workers.dev/ で）: Android で「画像つきで共有」→ X は、画像が添付され、URL も入った状態で開いた。「X」のボタンは画像なし（仕様どおり）。iPhone は未確認
  - リンクのプレビュー画像（OGP）は保留（人間の判断）。案: A 固定 1 枚 / B ステージごと（ビルド時に作る）/ C 結果ごと（Worker が必要）
- **領土**: 日本の領土はすべて地図に入れる。北方領土・竹島・尖閣諸島・離島も含める（人間の判断「そこに住む人が悲しむので」、2026-11-15）。サムネイルも、離島を含めたステージの地図全体で描く
- 未決: 「まるごと」の上限（人間があとで考える）、地域が 1〜3 しかないステージ、島だけのステージの扱い、所属未定地

## 共有
共有画像に載せるのは地図・ステージ名・タイムの 3 つだけ。Web Share API、使えなければ画像ダウンロード。

## 公開
**変更（2026-11-15）**: 本番は Cloudflare **Pages**（GitHub 連携、https://four-coloring.smooth-pudding.net/）。`smooth-pudding.net` の DNS は XServer にあり、VPS のサービスが動いているため、DNS を Cloudflare に移さずに済む Pages にした（Workers のカスタムドメインは DNS が Cloudflare にあることが前提）。開発用は Workers の `four-coloring-game-dev`。詳しくは `docs/DEPLOY.md`

GitHub（公開リポジトリ）→ Cloudflare Workers の静的アセット、自分のドメイン。

## 次の段階（仕様書の「要追加調査」より）
1. 国土数値情報（行政区域）の利用条件の確認（商用利用・出典表記・年次）。取得は 1 ファイルずつ、事前に robots.txt と利用条件を読んでから
2. ビルド時のデータ加工（`scripts/`、Python は uv）: 隣接計算 → 簡略化 → 飛び地のまとめ → 4 色解の存在確認
3. 地域区分の対応表（市区町村 → 地域名）を県ごとに作る。入門の地方区分、北海道、政令市、離島の扱いを決める
4. ダミーデータを `src/data/` の実データに置き換える
5. Cloudflare への公開設定
