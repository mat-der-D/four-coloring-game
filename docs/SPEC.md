# 仕様の要点

正本は[仕様書](https://claude.ai/artifact/5LsjGgoao8uW32vUDHdvr4)。ここは実装中に手元で見るための要約で、食い違ったら仕様書を優先する。

## ルール
- 地域をタップするたびに 4 色を循環（白には戻さない）。全域が着色済みで同色の隣接が 0 になったらクリア
- 同色の隣接境界は赤でハイライト（ON/OFF 切り替え、初期 ON）。OFF のときは全域を塗り終えても衝突が残る場合だけ「同じ色の隣りあいが n か所」と知らせる
- タイマーは最初のタップで開始、クリアで停止、0.1 秒単位
- 飛び地は同じ地域として扱い、色も一緒に変わる
- ピンチで拡大縮小、ドラッグで移動。動かさずに離したときだけタップ
- 記録は保存しない（localStorage も使わない）。アカウントもサーバー処理も持たない

## ステージ
入門（地方・4〜10 地域）／本編（県を地域に分けた市区町村・15〜25、上級「まるごと」30〜180）／全国（47 都道府県）。解放制はなく最初から全部選べる。ステージ間の隣接は扱わない。

## 共有
共有画像に載せるのは地図・ステージ名・タイムの 3 つだけ。Web Share API、使えなければ画像ダウンロード。

## 公開
GitHub（公開リポジトリ）→ Cloudflare Workers の静的アセット、自分のドメイン。

## 次の段階（仕様書の「要追加調査」より）
1. 国土数値情報（行政区域）の利用条件の確認（商用利用・出典表記・年次）。取得は 1 ファイルずつ、事前に robots.txt と利用条件を読んでから
2. ビルド時のデータ加工（`scripts/`、Python は uv）: 隣接計算 → 簡略化 → 飛び地のまとめ → 4 色解の存在確認
3. 地域区分の対応表（市区町村 → 地域名）を県ごとに作る。入門の地方区分、北海道、政令市、離島の扱いを決める
4. ダミーデータを `src/data/` の実データに置き換える
5. Cloudflare への公開設定
